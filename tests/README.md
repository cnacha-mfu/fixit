# 🧪 ชุดทดสอบ Playwright ต้นแบบ — FixIt (สัปดาห์ที่ 9)

เทสต์ 4 ตัว เดินตามแบบเดียวกับที่สาธิตในคาบ:

| ไฟล์ | ทดสอบอะไร | ผ่านเมื่อ |
|---|---|---|
| `main-flow.spec.js` | เส้นทางหลัก 6 ขั้น (แจ้ง → มอบหมาย → ซ่อม → ปิดงาน) | รายการแสดงสถานะ เสร็จสิ้น จริง |
| `validation.spec.js` | กรอกไม่ครบ | ไม่บันทึก + มีข้อความเตือนภาษาไทย |
| `security.spec.js` | ผู้แจ้งเปิดใบของคนอื่น | ⚠️ **เข้าไม่ได้ = ผ่าน** (เปิดได้ = ข้อมูลรั่ว) |
| `ai-failure.spec.js` | ปุ่ม AI เรียกไม่สำเร็จ | มีข้อความไทย + ปุ่มอื่นยังกดได้ ระบบไม่ค้าง |

## ติดตั้งครั้งแรก (~5 นาที)

```
npm install -D @playwright/test
npx playwright install chromium
```

## ตั้งค่าก่อนรัน

1. คัดลอก `tests/test-config.example.js` เป็น `tests/test-config.js`
   (ไฟล์นี้ถูก `.gitignore` กันไว้ เพราะมีรหัสผ่านบัญชีทดสอบ)
2. แก้ `BASE_URL` เป็น URL จริงของระบบที่ deploy แล้ว
3. สมัครบัญชีทดสอบ 3 บัญชีที่ `login.html` ตามอีเมลในไฟล์ (@example.com เท่านั้น)
   แล้วเข้า Firebase Console → `users` → แก้ role:
   `somying.test` → `technician` · `somsri.test` → `admin`
4. เฉพาะ `ai-failure.spec.js`: วางคีย์ปลอมทับใน `js/config.js` ชั่วคราวก่อนรัน
   (ทำให้ AI ล้มแบบควบคุมได้) — **เทสต์เสร็จแล้วใส่คีย์จริงกลับทันที**

## รัน

```
npm test                                 # รันทุกตัว
npx playwright test tests/security.spec.js   # รันทีละตัว
```

**จะเห็น:** เบราว์เซอร์ทำงานเบื้องหลัง แล้วสรุปผลเป็นรายการในหน้าจอ terminal
บรรทัดสุดท้ายประมาณ `4 passed` — ตัวไหน fail จะบอกว่าคาดหวังอะไรแต่เห็นอะไรแทน

## 🆘 เทสต์ fail — เดิน 4 กล่องก่อนแก้ทุกครั้ง

1. อ่านรายงาน: มันคาดว่าจะเห็นอะไร แล้วเห็นอะไรแทน
2. **กดเองด้วยมือ** ที่หน้าเว็บจริง — พังเหมือนกันไหม
3. เปิด `fixit-spec.md` เป็นกรรมการ — ระบบทำถูกตาม spec หรือเทสต์เขียนผิด
4. กดเองพัง = แก้โค้ด · กดเองใช้ได้ = แก้เทสต์ — **ห้ามแก้โค้ดเพื่อให้เทสต์ผ่านเด็ดขาด**

หมายเหตุ: เทสต์ผ่านบ้างไม่ผ่านบ้างโดยไม่ได้แก้อะไร มักเป็นเพราะรอไม่พอ —
เทสต์ชุดนี้รอด้วย `expect(...).toBeVisible()` (รอจนองค์ประกอบขึ้นจริง) ไม่ใช้การนับเวลาเฉย ๆ
